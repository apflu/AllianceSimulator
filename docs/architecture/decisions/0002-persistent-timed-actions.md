# ADR-0002：长期行动必须持久化

- 状态：已接受
- 日期：2026-07-29

## 背景

采矿、训练、旅行和制造会跨越现实时间。旧原型为对象启动内存协程并循环 `delay`，这种方式无法安全应对进程重启、多实例部署、重复投递和离线结算。

## 决策

每个长期行动都作为数据库记录保存，至少包含：

- 稳定 ID 和联盟 ID；
- 行动类型与规则版本；
- `started_at` 与 `finishes_at`；
- 玩家可见状态；
- 结算所需的输入快照；
- 幂等结算标记或等价约束。

Worker 从 PostgreSQL 认领到期行动，在事务中执行结算和写入通知发件箱。允许至少一次执行，但游戏结果必须等效于恰好一次。

## 后果

- 服务重启不会丢失行动；
- 可以观察积压、延迟和失败；
- 需要数据库约束、锁和幂等测试；
- 不能用 `asyncio.sleep()`、进程内 scheduler 或 Bot SDK task 作为权威计时来源；
- 初期不需要 Redis。未来替换调度基础设施时，不改变领域模型。
