# ADR-0001：使用 Python 实现权威后端

- 状态：已接受
- 日期：2026-07-29

## 背景

项目以 Discord、Telegram 等 IM 交互为主，包含大量会持续数分钟到数天的游戏行动和不断调整的领域规则，未来可能提供 Web 界面。当前不存在高频物理模拟或低延迟实时战斗需求。

## 决策

权威游戏后端使用 Python。Web 前端若出现，使用 TypeScript，并通过 OpenAPI 或显式 API schema 生成客户端类型，而不要求前后端共享实现语言。

基线工具为 Python 3.13+、uv、Pydantic、SQLAlchemy 2、Alembic、FastAPI、discord.py、aiogram、pytest、Hypothesis、Ruff 和 Pyright。

## 理由

- 游戏规则表达简洁，适合快速验证和修改玩法；
- Bot、Web API、数据处理和测试生态成熟；
- 当前负载主要是 I/O 和持久化调度，GIL 不是主要限制；
- 与旧 Java/Kotlin 原型相比，可减少框架和样板代码对领域设计的干扰。

## 后果

- 必须启用严格静态检查，并为领域规则提供充分测试；
- Python 对象不能充当数据库事务或跨进程锁；一致性由数据库约束和事务保证；
- 如果未来出现昂贵的批量战斗计算，可独立到进程池、专用服务或原生扩展，而不提前优化整个后端；
- Web 客户端通过 API 契约共享类型，而不是直接导入后端模型。

## 未选择方案

- TypeScript：全栈类型共享更直接，但当前阶段规则迭代的收益不如 Python 明显。
- Kotlin：协程和类型系统优秀，但旧 JVM 原型已表现出较高样板和框架耦合成本。
- Go/Rust：运行性能优秀，但当前业务不存在足以抵消开发成本的性能瓶颈。
