# 内容定义与存档兼容

## 稳定标识

材料、地点、舰船类型、技能和事件模板使用稳定的字符串 ID。ID 一旦进入迁移或玩家存档便不能重新分配给其他含义；显示名称可以独立调整。

Alpha 开始区分来源命名空间：SDE 派生内容使用 `eve:`，原创联盟内容使用 `asim:`，例如
`eve:type:587` 与 `asim:knowledge:fitting-theory`。SDE 数字 ID 不能被原创内容复用。每个 SDE 内容
快照同时记录 build number、artifact 摘要、导入器版本和 projection schema version；详细流程见
[SDE 内容接入规划](../EVE/sde-integration.md)。

## 规则版本

长期行动开始时冻结影响结算的结果和规则版本。例如，采矿行动保存预计产量，技能训练保存目标等级，因此部署新平衡数值不会改变已经开始的行动。

修改一套规则的含义时创建新版本号，旧版本必须保持可解释，直到所有引用它的存档均已迁移或自然结束。

## 事件快照

`EventOccurrence` 在触发时保存完整的可解析内容快照，包括：

- 模板 ID 与版本；
- 标题和正文；
- 选项 ID 与展示文本；
- 每个选项的受控资源效果；
- 默认选项和超时时间。

玩家处理旧事件时使用实例快照，而不是重新读取当前模板。这保证内容更新之后，已经展示给玩家的选项仍然具有原来的结果。

## 受控效果

事件内容不能执行任意 Python。MVP 只允许经过类型验证的资源增减效果，并在领域对象中验证正数数量。需要新增效果时，应扩展显式效果类型及其测试，而不是在 JSON 中放置代码、模块名或动态表达式。

## 兼容性检查

- 新内容版本必须保留读取既有快照的测试。
- 删除静态定义前必须确认没有运行中行动直接依赖它。
- 数据结构变化使用 Alembic 迁移，不在启动时偷偷修复存档。
- 无法自动迁移的内容变化必须先提供可审计的转换工具。
