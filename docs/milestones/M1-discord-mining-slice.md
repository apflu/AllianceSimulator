# M1：Discord 采矿纵向切片

状态：实现、自动验证与真实 Bot 连接预检完成；待 Discord 测试服务器玩家流程

## 玩家结果

玩家能够从零开始创建联盟、查看状态、开始采矿，在服务重启或玩家离线后仍然获得一次且仅一次的采矿收益和 Discord 通知。

## 玩家流程

1. 玩家执行 `/start`，创建联盟及初始角色、舰船和模块。
2. 玩家执行 `/status`，看到联盟资产、库存和当前行动。
3. 玩家执行 `/mine`，收到预计完成时间。
4. Worker 在行动到期后结算材料。
5. 玩家收到完成通知，再次 `/status` 可以看到资源增加。

具体命令名称可以在实现时调整，但应用用例和验收行为不得依赖 Discord 文案。

## 交付内容

- Discord 身份映射和三个入站命令；
- Character、Ship、Inventory、Location 和 TimedAction 的最小模型；
- 创建联盟、查询状态、开始采矿和完成行动用例；
- 数据库驱动的到期行动认领与重试；
- 事务性通知发件箱及 Discord 投递器；
- 对重复平台交互和重复 Worker 执行的幂等保护；
- 一种材料、一个地点、一个角色和一艘初始舰船的内容定义；
- 单元、集成和 Discord 适配器契约测试。

## 验收场景

### 正常流程

新玩家完成 `/start → /status → /mine`，到期后只获得一次预期材料并收到通知。

### 重复请求

Discord 重发相同 interaction 时，只创建一个联盟或一个采矿行动。

### 服务重启

采矿期间停止所有进程，超过截止时间后重新启动；行动最终结算且不丢失收益。

### 并发 Worker

两个 Worker 同时尝试认领同一行动，最终只有一个资源变更和一个逻辑通知。

### 非法操作

没有联盟、角色正忙、舰船不属于联盟或行动未到期时，返回稳定错误且不改变状态。

## 完成标准

上述场景自动化通过，并在一个测试 Discord 服务器完成一次人工冒烟测试。平台 token 仅来自运行环境。
