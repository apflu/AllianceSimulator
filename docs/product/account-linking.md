# 平台身份与账号策略

## MVP 决策

Discord 和 Telegram 身份在 MVP 中默认是两个独立的游戏玩家。平台适配器使用平台类型与不可变用户 ID 的组合查找 `PlatformIdentity`；显示名、用户名和群昵称均不参与身份判断。

因此，同一个人分别在 Discord 和 Telegram 执行 `/start` 时会得到两个独立联盟。这不是跨平台共享存档，但可以避免错误合并和账号劫持，同时不影响两个平台复用同一游戏规则。

## 明确禁止

- 不根据相同显示名自动绑定账号；
- 不接受用户自行声明另一个平台用户名作为所有权证明；
- 不把 Bot 所在群组或服务器当作玩家身份；
- 不允许平台回调直接提交内部 Player ID。

## 后续绑定方案

需要跨平台共享存档时，由已登录的一端生成短时、单次使用的绑定码，另一端确认后把新的 `PlatformIdentity` 关联到同一 Player。绑定必须记录审计信息，并处理两个身份已经各自拥有联盟时的冲突；MVP 不实现自动合并联盟。
